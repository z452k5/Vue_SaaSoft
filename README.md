# Управление учетными записями (Vue 3 + TypeScript + Pinia + Zod)

## Суть задачи

Тестовое задание заключалось в реализации формы управления учетными записями с возможностью:

- добавления и удаления записей,
- редактирования полей: Метка, Тип записи (LDAP / Локальная), Логин, Пароль,
- валидации обязательных полей и бизнес-правил,
- сохранения состояния в менеджере состояния с восстановлением при перезагрузке.

Основные правила по ТЗ:
- Метка: необязательная, ввод через `;`, каждая до 50 символов, хранится как массив объектов вида `{ text: "..." }`.
- Тип записи: `LDAP` скрывает поле пароля и сохраняет его как `null`, `Локальная` делает поле пароля обязательным.
- Логин: обязательный, максимум 100 символов.
- Пароль: обязателен только для типа `Локальная`, максимум 100 символов.
- Валидация срабатывает при `blur` для текстовых полей и при `change` для селекта.

## Стек технологий

- Vue 3 (Composition API) + TypeScript
- Pinia — глобальное хранилище, с сохранением данных в `localStorage`
- Zod — декларативная валидация данных и правил
- TailwindCSS + @tailwindcss/forms — утилитарная стилизация формы
- Heroicons — иконки для UI

Примечание: использование TailwindCSS — это личный выбор для удобства и прозрачности стилей. Если в проекте используется другой UI-фреймворк (например, Vuetify, Element Plus, Naive UI), адаптация не составит проблемы. Логика и структура изолированы от конкретного UI-решения.

Применение Zod рекомендую, так как он позволяет объединить статическую типизацию (TS) и рантайм-валидацию. Но при необходимости возможно заменить валидацию на vee-validate или кастомные проверки.

## Запуск проекта

```bash
npm install
npm run dev
```

## Реализовано

- Добавление и удаление записей
- Автоматическая валидация через Zod при редактировании
- Валидационные ошибки подсвечиваются в интерфейсе
- Преобразование поля «Метка» в массив объектов `{ text }`
- Сохранение всех данных в Pinia и их восстановление при обновлении страницы
- Адаптивная верстка на TailwindCSS

## Структура проекта

```
src/
 ├─ components/
 │   └─ AccountsForm.vue   # Основной компонент формы
 ├─ stores/
 │   └─ accounts.ts        # Pinia store с persist в localStorage
 ├─ validation.ts          # Zod-схемы валидации
 ├─ types.ts               # Общие типы данных
 ├─ App.vue, main.ts, style.css
```

## Пример работы валидации (Zod)

- При выборе LDAP пароль скрывается и сохраняется `null`.
- При выборе Локальная пароль обязателен.
- Каждая метка, введённая через `;`, превращается в объект `{ text }`.
- Ошибки подсвечиваются и отображаются под полем.

## Если вдруг

- UI легко заменить на любой другой фреймворк (Vuetify, Ant Design Vue, Naive UI, Element Plus).
- Валидацию можно переключить на vee-validate или встроенные правила, если в команде приняты другие стандарты.
- Логика хранится в отдельном store и не завязана на стилизацию.
